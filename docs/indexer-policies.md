# Indexer Policies

Indexer Policies add target-specific slot and trump analysis to RavenSeed's existing search and tracker-monitor results. Enable a policy under **Settings → Indexer policies**, choose an enabled qui indexer, edit the rules, and save. Policies are disabled until explicitly enabled. Existing search matching and Upload-Assistant submission work independently of this setting.

RavenSeed evaluates already-parsed release metadata. The result is one of **Equivalent**, **Missing Slot**, **Coexistence**, **Trump**, **Possible Trump**, **Not Eligible**, or **Unevaluated**. Each finding shows the observed slot, related target releases, objective improvements, missing evidence, and review reasons. “Missing” means no occupant was observed in a completed target search; it does not prove that the tracker lacks the torrent. A failed or incomplete target search is always unevaluated.

**Target releases considered** shows the actual target release name, indexer, reported size, slot relationship, and a link to the tracker result when qui provides one. Older saved findings contain only result IDs; run **Check again** on a monitor candidate or repeat a manual search to populate release names.

The slot editor offers separate axes for full discs, remuxes, encodes, WEB-DLs, WEBRips, HDTV, and other releases. Currently evaluated objective rules include correction over original (a REPACK, RERIP or REISSUE only over the same group's release, a higher revision such as REPACK2 over the same group's REPACK, and a PROPER over any group's original), explicit HDR relationships, same-service WEB-DL over WEBRip, within-class source priority, configured reputable group over NoGrp, season pack over episodes, and an optional encode total-size difference boundary. Total torrent size defines only an encode slot boundary; it never proves visual quality. The size boundary can be limited to resolution and codec pairs such as `1080p:AVC` (resolutions 480p, 576p, 720p, 1080i, 1080p, 1440p, 2160p and 4320p), and capped to a number of size slots: once every size slot is taken, an encode outside all boundaries competes with the nearest occupant.

Encode size tiers split encodes at a resolution into compact, up to a video bitrate limit, and transparent above it. For a tracker monitor torrent verified through Sonarr or Radarr download history, the video bitrate MediaInfo measured on the matching library file is used, matched by exact file size, with no margin: a measured 12 Mbps is compact under a 12 Mbps limit. Otherwise, and always for target releases, the video bitrate is estimated from the torrent size, the runtime and the named audio format. The runtime comes from the torrent's Sonarr or Radarr identity or from TMDb; season packs also need the season's episode count. An estimate within 10% of the limit, or a missing runtime, leaves the tier unknown: the encodes are treated as competing and the finding goes to review, never to a candidate. Encodes within 5% of each other's size share a tier without a runtime.

**Any pack of a season blocks its single episodes** refuses a single episode once the target lists any pack of that season, whatever its quality or provider. **Season pack beats single episodes** is the narrower trump between otherwise equal releases.

Some rules cannot be settled from a release name. When enabled, these send an otherwise occupied slot to review: a dual-audio release (Dual-Audio, DL or MULTi) against a release without that label, and a 2160p WEB-DL with lossless audio that may take an additional lossless slot.

Two untagged H.264 releases at 1080p or below are compared as SDR. Elsewhere an absent HDR tag on either side keeps a trump in review. An absent HDR tag is labeled **unmarked**, not assumed SDR. Missing required provider or codec metadata on the source leaves the policy unevaluated. A target release with missing metadata only matters when it could occupy the source's slot: one whose stated metadata already differs is another slot, and a definite occupant still decides. A target that might be the occupant, or a same-titled movie listed without a year, prevents a Missing Slot, Coexistence or Trump result.

Four built-in generic presets, Ruleset 1 through Ruleset 4, capture only rules that can be observed from release names and sizes. Ruleset 4 includes its HDR ranking graph, including PQ10, and marks proposed HDR trumps for manual review because the rules require comparable quality. The presets deliberately omit tracker upload compliance requirements. Select a preset to populate an editable draft, then save it for the target indexer. **Import / export JSON** displays the draft for export and accepts pasted policy JSON for import. Each save creates an immutable snapshot; saved monitor findings and search analyses refer to the version used for their evaluation. A policy edit changes future evaluations, and the changed snapshot also prevents an old cached search analysis from being reused. Use **Recheck candidates**, labelled with the candidate count once it loads, after saving to queue fresh target searches for existing monitor rows. Paused monitors remain paused until resumed.

Manual-review rules can flag competing releases with distinct groups or sources for visual or master comparison; occupying the same slot alone does not establish a possible trump, but RavenSeed has no comparison screenshots or trusted bitrate, track, activity, or defect evidence. It does not automatically apply rules based on superior visual quality, audio mixes, subtitles, chapters, full-disc provenance, seeder inactivity, encode bitrate tiers, or TV air-date timing. Upload-Assistant still performs its own duplicate and upload checks. A **Possible Trump** monitor finding can be explicitly sent to UA after review; RavenSeed never uploads a policy finding automatically.

The API exposes `GET /api/v1/policy-presets`, `GET /api/v1/indexer-policies`, and `GET`, `PUT`, `DELETE` on `/api/v1/indexer-policies/{indexerId}`. `POST /api/v1/indexer-policies/{indexerId}/evaluate` accepts a saved `searchId`, `candidateResultId`, and optional `targetResultIds` for debugging. `POST /api/v1/indexer-policies/{indexerId}/recheck` queues monitor candidates for fresh checks. Policy and candidate APIs use RavenSeed's normal authentication and origin checks.

Internal releases matter only on their home tracker, and nothing RavenSeed reads says whether a release is a tracker's internal; a scene `INTERNAL` tag means something else. List the tracker's own groups under **Internal groups on this tracker** in that tracker's policy. The list never affects any other target. Choose how that tracker treats them: **own slot** lets internal and non-internal releases coexist while two internals compete as usual, and **extra slot or trump: review** sends an internal facing an occupied non-internal slot to review, since an internal may take an additional slot or trump only when equivalent or superior.

**Banned groups on this tracker** lists groups the target tracker refuses. A release from one is never offered: tracker monitors mark it Not Eligible without searching the target, and search results show the same. When a target release in the candidate's slot comes from a banned group and the candidate's group is allowed, the candidate is a Trump over it; the usual identity and HDR checks still apply, and tracker staff decide. A banned release in another slot changes nothing. The list applies only to this target. A release matches a listed group by its parsed group or by its name ending in `-` and the listed name, ignoring case, dots, spaces and underscores, so names such as `YTS.MX`, `BEN THE MEN`, `ALCAIDE_KIRA` and `WEASLEY[HONE]` work as written. Listing `YTS.MX` does not ban a group named `MX`.
